# Safari 启动兼容与可调整触控

用户报告：iPhone Safari 中点击后白屏并重新加载。当前环境没有可用浏览器 / iPhone 实机测试入口，因此没有捕获到该设备的原始崩溃堆栈，不将任何单一猜测写成已确认根因。

## 已修改的启动路径

- 原版第一次点击会执行引擎音频播放，音效也会创建引擎音频节点。Web 版改用 Dummy 引擎音频驱动，不创建这些播放器或采样缓存。
- 声音由网页独立处理，默认关闭，仅在用户显式开启后创建 AudioContext。音乐转码为 iPhone 通用的 MP3，播放失败单独处理，不中断游戏。
- 从 iframe 嵌入改为同页运行，画布固定 960×540，CSS 适配横竖屏，不按 Retina DPR 放大渲染缓冲。Web 最大帧率 60，恢复后台时限制单帧补算。
- 引擎 WASM 分片改为顺序流式响应，移除先同时下载两个 ArrayBuffer 再合成 Blob 的方式。
- Web 打包不包含引擎侧音乐、测试或网页源码资源；网页音乐懒加载，降低首屏包体和内存。
- 版本化引擎分片、游戏包和网页资源请求，避免旧缓存混用。
- 保留加载错误、脚本异常、引擎退出和图形连接中断的可见错误层及复制信息按钮；只有用户点“重新加载”时才会调用页面重载。

这些变更覆盖首触音频、画布资源和启动错误处理；真实 iPhone 效果仍需用户复测。若仍有整个标签页重载，可结合 Safari 崩溃日志或新错误面板继续定位。

## 新触控 UI

- 左侧模拟摇杆，横向比例控制移动 / 慢推，松手回中。
- 右侧跳跃与喷雪两个大按钮，喷雪可按住连发，跳跃按下触发。
- 指针独立追踪，支持移动、跳跃和喷雪同时操作；取消、失焦、后台和调整布局时释放输入。
- 设置可分别修改摇杆、跳跃、喷雪的大小、横纵位置，并调整透明度。
- 进入拖动布局模式时暂停游戏，拖动后完成可恢复原来的暂停状态。
- 布局存储在当前设备的 localStorage；数据损坏或存储不可用时回退默认布局。
- 适配刘海安全区及横竖屏，控件限制在可见范围，提供恢复默认。

## 验证

- 46 项原有玩法回归。
- 15 项 Godot Web 输入桥接检查，包含重复开始不创建音频节点、模拟摇杆朝向、三项并发输入与暂停释放。
- 20 项网页模型与加载检查，包含多指、保存恢复、5 组横竖屏边界、默认不重叠、顺序引擎加载、资源缺失错误与缓存版本。
- 4 项 DOM 模型集成检查，包含开始按钮反复点击不重载、调整大小和拖动保存、独立指针释放、回调异常显示且不递归。

网页测试是 Node 下的逻辑 / DOM 模型测试，不是浏览器或 iPhone 实机测试。

Web 构建：先 Godot 导出生成 game.html，再运行 `python3 web/build_web.py <导出目录>`，最后将导出目录作为静态站点部署。

## 后续摇杆回中修复

收到偶发一直向右的反馈后，为 Safari 增加原生 Touch Events 与触摸 ID 管理，核对当前触摸列表以清理已离开的手指；Pointer Events 则增加页面捕获阶段的结束监听，捕获失败和滑出控件也可释放。失焦、转屏和视口变化主动回中并释放捕获。构建时同时版本化间接导入的输入模块，避免新页面混入缓存中的旧控制逻辑。

本轮 22 项控制与加载模型、11 项 UI 事件模型检查通过，含三指操作、100 次 ID 复用、漏结束事件、全局松手以及触屏编辑布局；另保留 15 项 Godot 输入桥接验证。详细姿态与玩法记录见 JUMP_REVIEW.md。上述仍属模拟和无界面检查，没有 iPhone Safari 实机复测结果。
